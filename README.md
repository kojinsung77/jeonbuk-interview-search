# 전북 면접사례 자료실

전북특별자치도교육청 면접사례모음집을 대학·학과·전형·질문으로 검색하고, 사례별 원본 PDF를 함께 읽는 교내 상담용 웹앱입니다.

## 사용

- 안내받은 입장 비밀번호로 자료실을 엽니다. 비밀번호는 서버에 보내지 않습니다.
- 여러 단어를 띄어 쓰면 해당 단어를 모두 포함한 사례를 찾습니다.
- 연도·계열·대학·면접 형식 필터, 질문 보기, 이 기기의 즐겨찾기를 제공합니다.
- 원본 PDF의 확대·축소, 쪽 이동, 새 탭 열기, 다운로드를 지원합니다.
- 정리된 답변은 학생의 경험 기록이며 모범답안이 아닙니다.
- 문항 JSON이 없는 사례는 기본 정보 검색과 원본 열람만 가능합니다. 면접 형식은 ‘미확인’으로 분류합니다.

## 파일 구조

```text
build.py                 엑셀·문항 JSON 병합 및 암호화
publish.ps1              GitHub Pages 게시
requirements.txt         빌드용 패키지
public/                  실제 웹사이트 / 이 폴더만 배포
  index.html
  app.js
  style.css
  vendor/                PDF.js 6.3.289, Apache-2.0
  data/meta.json         공개 암호화 설정(소금값·반복 횟수)
  data/cases.bin         암호화된 전체 사례 목록과 문항
  data/pdf/c0001.bin     번호로 이름을 바꾼 암호화 PDF
```

원본 PDF, 엑셀, 문항 JSON, 비밀번호는 이 저장소에 올리지 않습니다. `.build-cache.json`은 로컬 증분 빌드용이며 저장소에서 제외합니다. 원본 자료는 앱 폴더 밖에 보관합니다.

## 로컬 실행

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory public
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다. 파일을 더블클릭하는 `file://` 방식은 지원하지 않습니다.

## 자료 갱신

앱 상위 폴더에 다음 구조로 원본을 둡니다. 폴더 앞의 번호와 설명은 자유롭게 정할 수 있습니다.

```text
자료 폴더/
  03_전북교육청 면접사례집(2026)/
    사례목록_2026_전체.xlsx
    사례별분할_계열이름/*.pdf
    json/2026_계열이름.json
  jeonbuk-interview-search/
    build.py
```

엑셀 `전체목록` 시트에 `파일명, 연도, 계열, 대학, 학과, 전형, 원본PDF 쪽, 쪽수` 열이 필요합니다. `원본PDF 쪽`은 계열별 원본 내 쪽 번호이며, 책에 인쇄된 쪽수와 다릅니다. 문항 JSON은 PRD v1의 `{"meta": {...}, "cases": [...]}` 구조 또는 사례 배열을 받습니다. 각 사례의 `pdf` 마지막 파일명이 엑셀과 분할 PDF에 정확히 일치해야 합니다. 대학·학과·전형 불일치, 중복 파일명, 연결되지 않은 문항, PDF 쪽수 불일치는 빌드를 중단합니다.

```powershell
python -m pip install -r requirements.txt
python build.py --password
python build.py --password --verify
```

`--password` 뒤에 값을 쓰지 않으면 숨김 입력을 받습니다. 실제 비밀번호를 명령문, 저장소, 문서에 적지 마세요. 같은 비밀번호로 빌드하면 변경된 PDF만 암호화하고 전체 검색 목록은 다시 만듭니다. 자료 갱신 후 게시 스크립트를 실행합니다.

## 2024·2025년 추가

해당 연도도 사례별 PDF로 분할한 뒤, 같은 구조의 `사례목록_2024_전체.xlsx`, `사례목록_2025_전체.xlsx`와 선택적인 문항 JSON을 준비합니다. 통합 원본 PDF만으로 자동 분할하거나 문항을 추출하지는 않습니다.

```powershell
python build.py --years 2024 2025 2026 --password
python build.py --password --verify
```

새로 만든 연도는 필터에 자동으로 나타납니다. `--years`에는 유지할 모든 연도를 넣으세요. 생략한 연도는 새 배포에서 제외됩니다. 원본 경로가 다른 경우 `--source "자료 폴더"`를 지정합니다. 실제 파일명이 그대로 유지되는 한 사례 ID와 즐겨찾기는 문항 추가나 엑셀 순서 변경에도 유지됩니다.

## GitHub Pages 게시

소스는 `codex/app`, Pages 배포물은 `gh-pages` 브랜치를 사용합니다. 게시 스크립트는 `public` 폴더만 배포합니다. 최초 저장소 생성과 Pages 설정 후:

```powershell
./publish.ps1
```

원본 자료를 추가한 뒤에는 먼저 `build.py`로 갱신하고 검증하세요. 게시 전 스크립트가 평문 PDF·엑셀·JSON과 임시 파일이 배포물에 없는지 확인합니다. GitHub Pages 설정은 `gh-pages` 브랜치, 루트(`/`)입니다.

## 보호 방식과 운영 주의

- AES-256-GCM, PBKDF2-SHA256 250,000회, 16바이트 무작위 salt, 암호화마다 새로운 12바이트 IV를 사용합니다.
- 각 파일의 경로를 인증 데이터에 묶어 파일 바꿔치기를 검출합니다. PDF 해시도 암호화된 목록 안에 저장해 복호화 후 검사합니다.
- 웹사이트는 외부 분석 도구나 외부 실행 스크립트를 사용하지 않습니다. PDF.js도 같은 사이트에서 제공합니다.
- 탭 새로고침 시 입장을 유지하기 위해 복호화 키만 `sessionStorage`에 임시 저장합니다. 비밀번호 원문은 저장하지 않습니다. 공용 PC에서는 **잠금**을 사용하세요. 브라우저의 탭 복원 기능은 세션을 복원할 수 있습니다.
- 즐겨찾기는 `localStorage`에 사례 ID만 저장합니다. 검색·사례 공유 정보는 URL의 fragment(`#`)에 저장하여 일반 HTTP 요청에 실리지 않습니다. 공유 링크 자체에는 검색어가 보이므로 전달 대상을 확인하세요.
- 비밀번호 변경 시 새 비밀번호로 전체 빌드·게시합니다. 현재 사이트에서는 이전 비밀번호를 쓸 수 없지만, GitHub의 이전 커밋과 이미 받은 암호화 파일에는 이전 비밀번호가 계속 작동합니다. 기존 파일이나 다운로드를 소급해 회수하는 수단이 아닙니다.
- 단일 공유 비밀번호 방식이므로 비밀번호를 아는 사람은 전체 자료를 보거나 다운로드할 수 있습니다. 강한 비밀번호와 제한된 공유가 필요합니다.
- 자동 검사는 문항의 전화번호·이메일·주민등록번호·명시된 개인정보 항목을 가림 처리하고, 텍스트 PDF에서 직접 식별자 후보를 발견하면 중단합니다. **스캔 이미지 속 개인정보는 텍스트 검사로 확인할 수 없으므로 원본의 별도 육안 검수가 필요합니다.** 내용에 섞인 학생 이름이나 출신 학교가 자동으로 완벽히 제거되는 것은 아닙니다.
